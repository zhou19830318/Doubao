# HeyClawy 产品需求文档 (PRD) v2.0

## 1. 产品概述
- **产品名称**：HeyClawy
- **硬件平台**：微雪 ESP32-S3-Audio-Board + 微雪 1.47 寸触摸屏（172×320）
- **产品定位**：一款“语音优先”的桌面智能终端。设备通过语音与部署在云服务器的 OpenClaw 服务端对话，完成任务、设置定时提醒、查询信息，并将结果以语音 + 屏幕 UI 的方式反馈给用户。
- **关键约束**：OpenClaw Gateway WebSocket 仅支持 JSON 文本帧（不接收二进制音频）。设备侧需要完成唤醒、录音与 STT（本地或云端），并将文本发送给 OpenClaw；TTS 可由云端生成音频或由设备侧本地播放。

## 2. 目标用户与使用场景
- **目标用户**：极客、开发者、智能家居爱好者
- **典型场景**：
  - 语音问答：查询天气/时间/知识点
  - 任务管理：布置任务、设置 cron/提醒，到点自动播报
  - 本地音乐：语音指挥播放 SD 卡 MP3
  - 状态面板：实时展示 OpenClaw 连接与使用情况

## 3. 硬件规格与边界
- **SoC**：ESP32-S3（16MB Flash，8MB PSRAM）
- **音频**：ES7210（麦克风 ADC）+ ES8311（扬声器 DAC），I2S 16kHz/16-bit
- **显示/触控**：1.47 寸 172×320（驱动 JD9853，SPI）+ AXS5106L 触摸屏（I2C）
- **存储**：MicroSD（SDMMC 1-bit，FATFS）
- **指示**：WS2812 RGB 环形灯（GPIO38）
- **按键**：板载 BOOT 键（GPIO0）+ IO 扩展按键（P1.1-P1.3）

## 4. 系统架构（端到端）

### 4.1 数据流
1. **唤醒**：WakeNet 检测到唤醒词（默认 “Hey Jarvis”）进入激活态
2. **采集**：设备录音（暂停唤醒引擎，避免 I2S 争用）
3. **识别**：STT 将语音转为文本（本地或云端）
4. **对话**：设备通过 WebSocket 调用 OpenClaw `chat.send` 发送文本
5. **反馈**：设备接收 OpenClaw `chat` 事件（delta/final），更新 UI 气泡并触发 TTS
6. **播报**：播放 TTS（与 MP3 播放互斥），可被触摸/按键打断
7. **记录**：将对话以文本形式追加写入 SD 卡当日日志

### 4.2 OpenClaw Gateway 协议要点
- 连接：`connect.challenge` → `connect`（ED25519 设备身份签名）→ `hello-ok` 快照
- Chat：`chat.send` 请求后，服务端推送 `chat` 事件（`state: delta|final|error`）
- 状态：`tick`（心跳），`health`（周期健康推送），按需拉取 `usage.status` / `sessions.list`
- 重要约束：
  - 所有帧为 JSON 文本
  - `id` 必须是字符串
  - `delta` 与 `final` 同时存在时，处理 `final` 需要覆盖（不能追加）以避免重复文本

## 5. 功能需求

### 5.1 语音对话与任务能力
- **对话能力**：用户可通过语音与 OpenClaw 对话，包括：布置任务、设置定时提醒、查询问题等
- **反馈方式**：
  - 屏幕：以聊天气泡显示用户与助手的文本内容 + 时间
  - 语音：将 OpenClaw 最终回复通过 TTS 播放
- **打断能力**：
  - 触摸屏可取消：`LISTENING`（取消录音）、`SPEAKING`（停止 TTS）、`PLAYING_MP3`（停止音乐）
  - BOOT/按键可作为紧急打断入口（按键优先级高于语音）

### 5.2 OpenClaw 状态可视化
设备屏幕需要展示 OpenClaw 的关键状态与指标，至少包含：
- **连接状态**：未连接 / 连接中 / 已认证 / 断线重连
- **运行时间**：OpenClaw uptime（来自 `hello-ok` 或 `tick` 计算）
- **模型信息**：当前会话/agent 使用的模型（来自 `sessions.list` 或快照字段）
- **Token/用量**：
  - token 统计（来自 `sessions.list` 的会话统计）
  - 用量窗口（来自 `usage.status`，注意 providers 可能为空）

### 5.3 SD 卡：聊天日志与本地音乐
- **聊天日志**：
  - 每天一个文件，命名：`/chat/YYYY-MM-DD.txt`
  - 记录内容：时间戳、方向（USER/ASSISTANT）、文本
  - 写入策略：追加写；遇到时间未同步时先暂存，时间同步后补写
- **音乐存储**：
  - 默认目录：`/music/`
  - 支持 `*.mp3`（可扩展 `*.wav`）
  - 启动或插卡后扫描索引，显示可播放列表（按文件名排序）
- **语音播放控制**：
  - 用户通过语音对 OpenClaw 下达“播放本地音乐”类指令
  - OpenClaw 通过设备控制标签下发播放命令（示例见 5.4）

### 5.4 设备控制标签（来自 OpenClaw）
OpenClaw 可在回复文本中插入设备控制标签，设备执行后需从 UI/TTS 文本中剥离标签。

#### 5.4.1 MP3 控制指令
- `[DEVICE:mp3=play:<filename>]`：播放指定文件（相对 `/music/`）
- `[DEVICE:mp3=pause]` / `[DEVICE:mp3=resume]`
- `[DEVICE:mp3=stop]`
- `[DEVICE:mp3=next]` / `[DEVICE:mp3=prev]`
- `[DEVICE:mp3=seek:<seconds>]`：跳转进度（可选）

#### 5.4.2 通用设备指令（已有能力扩展）
- 音量、亮度、RGB、sleep 超时、webserver 开关、reboot 等（以资源文档为准）

### 5.5 屏幕 UI 需求

#### 5.5.1 顶部系统状态栏
最上方固定状态栏，显示：
- WiFi 状态（断开/连接中/已连接，RSSI 可选）
- OpenClaw 状态（断开/连接中/已连接/异常）
- 电量（百分比或电压；若无硬件电量计，则显示占位/未知）

#### 5.5.2 聊天气泡
- 气泡包含：文本内容 + 时间（HH:MM）
- 支持用户/助手双向不同样式（左右/颜色）
- 长文本处理：折行与裁剪；保留最近 N 条（N 可配置，默认 20）

#### 5.5.3 底部状态机栏
最下方显示设备状态机，至少包含：
- `SLEEP` / `ARMED`（待激活） / `IDLE` / `LISTENING` / `THINKING` / `SPEAKING` / `PLAYING_MP3`
- 当 OpenClaw 侧处理出现阶段信息时（例如 run started/processing），需要映射到本地 `THINKING`/`SPEAKING` 等，并显示简短子状态（例如 “WS:chat.delta”）

### 5.6 RGB 状态灯
RGB 环形灯用于表达当前状态机（需与 UI 状态一致）：
- `LISTENING`：绿色脉冲/旋转
- `THINKING`：蓝色呼吸
- `SPEAKING`：白色/青色呼吸
- `PLAYING_MP3`：彩虹或音乐律动
- `ERROR`：红色闪烁
- `SLEEP`：低亮暖色常亮或关闭（取决于功耗目标）

### 5.7 唤醒、退出激活与睡眠
本产品存在“唤醒激活态”与“睡眠态”两级节能逻辑：
- **唤醒词激活**：检测到唤醒词进入 `LISTENING`
- **20 秒无对话退出激活**：激活后如 20 秒内没有有效对话（未触发发送到 OpenClaw 或无用户语音输入），退出到 `ARMED/IDLE`
- **60 秒进入睡眠**：处于激活/待机超过 60 秒无有效交互，进入 `SLEEP`：息屏 + 降低 RGB 亮度
- **睡眠唤醒方式**：按下 BOOT 键进入 `ARMED`（待激活）状态（不直接开始录音，等待唤醒词或下一次交互）

## 6. 性能、安全与可靠性
- **响应延迟**：从用户结束说话到听到首段语音回复目标 1.5–2.5 秒（取决于网络与模型）
- **音频互斥**：TTS 与 MP3 必须互斥，任何一方开始前需中止另一方
- **网络鲁棒**：云端 WebSocket 断连自动重连；连接阶段需避免默认 ping 超时导致认证失败
- **密钥安全**：设备身份密钥存储于 NVS/安全区，严禁以日志输出或写入 SD

## 7. 验收标准（摘要）
- 唤醒词可稳定激活；20 秒无交互自动退出；60 秒进入睡眠；BOOT 键可从睡眠进入待激活
- 语音对话端到端可用：语音→STT→OpenClaw→TTS→扬声器
- 屏幕可见：顶栏（WiFi/OpenClaw/电量）、气泡（内容+时间）、底栏（状态机）
- SD 卡每天一个聊天日志文件可持续追加；语音指挥可播放本地 MP3 且显示名称/时长/进度
